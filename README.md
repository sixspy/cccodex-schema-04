# cc-schema-lab

CC_Codex 二期（26.11）**数据工程**产品线：**契约换版台**（aiohttp + 原生 JS SPA + SQLite）。

## 一句话骨架（自有，非外仓抄题）

**表契约版本登记 → 破坏性检查 → 换版应用 → 目录对账**

与现有九线正交（不是采集、ETL、同步、解析、编排、摄取、留存、清单、水印）。
不碰外仓常见指纹（Feed 归并 / CDC 游标 / 质检签发 / Slicegate 类仓名）。

## 领域

- **所属领域**：数据工程
- **子方向**：数仓与数据湖（表契约 / 换版闭环）

## 技术栈

| 层 | 选型 |
|----|------|
| 后端 | Python 3.12、aiohttp、SQLite |
| 前端 | 原生 JS SPA（全中文），暖杏纸面 + 墨绿强调；顶栏胶囊导航 |
| 测试 | pytest + pytest-aiohttp（本地秒级闭环，优先于 compose） |

## 基线已通主链

1. 表契约版本（表名 / 版本号 / 现行或草稿）
2. 对候选字段做破坏性检查（删列 / 改类型）
3. 换版应用（草稿升现行，旧现行停用）
4. 契约与目录表对账

## 父表血缘齐套（本期功能）

**规则**：挂父表血缘边的子表，父表缺边时不得升现行；齐套与升版必须互相核对，偏了就拒。

**门槛只取一边——打开即冻结缺边快照**（`Config.GATE_MODE = "snapshot"`）：

- 打开子表升版卡片的那一刻，按父表**现行**契约冻结一张缺边快照；之后齐套裁决、
  子表升版都只认这份快照。**提交瞬间当场重扫父表缺边**那一侧不实现、不混挂。
- 冻结快照后父表改边：快照只会被**作废或重拍**，绝不回头重扫改写已有裁决。
  卡片上会亮“血缘已变动，快照不再代表当前血缘”，要求显式重新冻结。
- 快照一旦裁决即成留证；重新冻结只在草稿阶段可用。

**四处联查**（同一份证据，芯片与凭证号必须对齐）：

| 位置 | 内容 |
|------|------|
| 依赖目录 | 每条血缘边只亮**快照芯片**（缺边 / 齐全 / 未冻结 / 已作废）+ 凭证号；可在此接边、撤边 |
| 父表详情 | 父表现行字段 + 被哪些子表列引用，以及引用方快照里的边芯片 |
| 子表升版卡片 | 打开即冻结；点齐套 → 裁决；齐套放行才可升现行 |
| 进度水线 | 冻结 → 齐套结果 → 目录凭证；**隔离时亮隔离凭证号**，并注明子表不得升现行 |

**点齐套的判定（一次改写）**：

- 快照缺边 → `隔离`，子表升版接口回 409「父表血缘缺边，子表已隔离，禁止升现行」；
- 快照齐套 → `齐套放行`，子表升版接口放行，并把齐套凭证写进目录与升版流水；
- 两人同时点齐套：`BEGIN IMMEDIATE` + `UNIQUE(snapshot_id)` 保证只落一条裁决，
  后到者回放原结果，不会双写子表客态。

**对账回看**：只读冻结快照与裁决留证，不重扫父表；报表里的齐套结论与卡片芯片同源。

**凭证号**：`SNAP-<快照序号>-<血缘指纹前六位>`，冻结 / 放行 / 隔离 / 升版共用一号。

预留切口（未做，供后续功能题）：双写迁移 vs 锁表切流、换版失败闭、跨表依赖冻结、回滚窗口等。
